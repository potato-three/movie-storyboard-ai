# 🎬 Movie Storyboard AI · 电影分镜提取工具

把一段电影 / 视频丢进去，自动完成 **镜头切分 → 关键帧提取 → 运动分析（机位 / 主体方向 / 强度）→ 结构化分镜本导出**，
为 AI 视频创作（分镜复用、角色一致性、图生视频）提供第一块拼图。

> 面向创作者的 AI 视频工作流第一阶段：先把「分镜」和「这一镜是怎么动的」自动化。

---

## ✨ 功能特性

- **自动镜头切分**：基于 PySceneDetect 内容检测，自动找到每个切换点，灵敏度可调。
- **关键帧提取**：每个镜头自动取中间帧作为代表画面。
- **运动分析（v0.2 新增）**：用光流自动判断每一镜的
  - **机位运动**：固定机位 / 左右摇移（pan）/ 上下俯仰（tilt）/ 推近拉远（zoom）；
  - **画面主体方向**：主体向左 / 向右 / 向上 / 向下等；
  - **运动强度**：无 / 弱 / 中 / 强；
  - 并额外生成一张**运动箭头图**，把「这一镜怎么动」画出来（橙色＝机位、红色＝主体、绿色＝局部运动残差，推 / 拉用四角箭头标注）。
- **三档速度**：精确（逐帧）/ 平衡（隔帧，默认，约快一倍）/ 快速（隔两帧）。
- **流式进度**：长片边切边出结果，每检测到一个镜头就显示一帧并推进进度条，不用干等。
- **镜头浏览器**：大图配滑块，可拖动 / 上一镜下一镜 / 点击底部缩略图快速跨时间轴定位，关键帧与运动图一键切换。大图为深色播放器底，切换时柔和淡入、松手才加载，滚轮不会误跳镜头，长时间快速浏览不刺眼。
- **三种导出格式**：
  - `HTML` —— 图文版分镜本，浏览器打开逐镜查看，内嵌压缩缩略图（文件小、可编辑描述列）；
  - `CSV` —— Excel 直接打开二次编辑（UTF-8 BOM，不乱码）；
  - `Markdown` —— 直接贴进 GitHub / 笔记。
- **文件自动收口**：原始视频和每次结果分别放进项目下两个中文文件夹，不散落系统临时目录。
- **两种使用方式**：Gradio 网页（上传即用）＋ 命令行（批量处理）。

## 📦 安装

需要 Python 3.10+。

```bash
# 1. 克隆（或下载）本项目
git clone https://github.com/potato-three/movie-storyboard-ai.git
cd movie-storyboard-ai

# 2. 安装依赖
pip install -r requirements.txt
```

## 🚀 使用方法

### 方式一：网页界面（推荐新手）

```bash
python app.py
```

运行后浏览器自动打开 `http://127.0.0.1:7860`：
把视频放进项目下的 **`原始视频/`** 文件夹（或直接在网页上传）→ 选择灵敏度与速度档 → 点「开始提取分镜」
→ 在镜头浏览器里查看，结果自动保存，可一键打开结果文件夹。

- **本机使用**：双击 `启动分镜工具.bat`（Windows）。
- **局域网分享**（同一 WiFi 下的手机 / 同学电脑）：服务已绑定 `0.0.0.0`，
  浏览器访问 `http://你的局域网IP:7860`。
- **公网分享**：建议部署到 [Hugging Face Spaces](https://huggingface.co/spaces)（免费、永久链接）；
  Gradio 自带的 `*.gradio.live` 临时隧道在部分网络下无法创建。

### 方式二：命令行

```bash
# 把视频放进「原始视频」文件夹，直接运行（自动处理其中第一个视频）
python main.py

# 指定视频
python main.py "D:\videos\your_movie.mp4"

# 调整灵敏度（数值越小，切出的镜头越多）
python main.py your_movie.mp4 --threshold 22

# 选择速度档：精确 / 平衡 / 快速
python main.py your_movie.mp4 --mode 快速

# 只切镜头、不做运动分析（最快）
python main.py your_movie.mp4 --no-motion
```

## 🗂️ 结果在哪、长什么样

所有数据都在**项目目录**下（想放到更大的盘，把整个项目文件夹拷过去即可）：

```
movie-storyboard-ai/
├── 原始视频/                     # 把原片放这里（不会被上传到 GitHub）
├── 分镜结果/                     # 每次提取一个独立结果文件夹
│   └── 影片名_分镜结果_20260920_2347/
│       ├── 关键帧/               # shot_0001.jpg、shot_0002.jpg …（原图分辨率）
│       ├── 运动图/               # shot_0001_motion.jpg …（带运动箭头）
│       ├── 分镜表.html           # 图文分镜本（推荐打开这个）
│       ├── 分镜表.csv            # Excel 用
│       ├── 分镜表.md
│       └── 提取信息.txt          # 本次参数、帧率、镜头数等元信息
├── storyboard/                  # 程序源码
├── app.py / main.py
└── requirements.txt
```

分镜表字段：**镜号 / 开始时间 / 结束时间 / 时长 / 机位运动 / 主体运动 / 强度 / 描述（可编辑）/ 关键帧**。

## 🧭 灵敏度阈值怎么调

| 阈值 | 适用场景 |
|---|---|
| 18 ~ 25 | 动作片、动画、MV、快剪短视频 |
| 27（默认） | 大多数电影、剧集 |
| 30 ~ 40 | 文艺片、纪录片、长镜头多的内容 |

> 阈值越小越敏感、切出的镜头越多；如果一个完整镜头被错误切碎，就调大一点。

## ⚡ 三档速度会影响准确性吗？

基本不影响**镜头边界**和**运动大方向**，原理是：

- **隔帧扫描**：相邻帧内容几乎一样，每隔 1～2 帧比对一次，照样能撞到镜头切换的那一帧，速度近似翻倍；
  只有极短（几帧）的闪切可能在快速档漏掉，需要逐帧核对时用「精确」。
- **缩小画面算运动**：光流在缩小后的灰度图上计算，牺牲的是细微局部纹理，摇 / 移 / 推 / 拉和主体大方向属于宏观位移，不受影响。
- 关键帧本身始终按**原始分辨率**保存，缩小只发生在运动计算内部。

## 🧰 技术栈

| 环节 | 技术 |
|---|---|
| 镜头切分 | [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) |
| 视频 / 图像处理、光流 | OpenCV（Farneback 稠密光流 ＋ Lucas-Kanade 稀疏光流） |
| 数据处理 | NumPy / Pandas / Pillow |
| 网页界面 | Gradio |
| AI 镜头描述（规划中） | GLM-4.6V / Qwen-VL |

## ⚠️ 说明

- 视频文件与含画面的结果**只保存在本地**，默认被 `.gitignore` 忽略、不会上传到公开仓库，请注意影视版权，仅用于个人学习创作。
